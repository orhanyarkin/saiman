# M1 design: x402 starter and first paid endpoint

Approved 2026-09-28. Decisions: ADR-0008 (native x402 v2), ADR-0009 (secrets), ADR-0006 amendment (source-side redaction). This file is the shared interface contract for the M1 tasks.

## Wire protocol
x402 **v2**, `exact` scheme on EVM only. Headers (base64 of JSON): `PAYMENT-REQUIRED` (402 response), `PAYMENT-SIGNATURE` (client retry), `PAYMENT-RESPONSE` (successful response). Spec: `specs/x402-specification-v2.md` and `specs/transports-v2/http.md` in github.com/x402-foundation/x402. The official Java SDK in that repo (`java/`) is v1 and a reference only.

Facilitator: `https://x402.org/facilitator` (`POST /verify`, `POST /settle`, `GET /supported`), free, no key.

## Testnet constants, enforced in code
```java
// io.github.orhanyarkin.x402.core.TestnetAssets
```

No network/asset property exists. Server offers only these; client rejects any other requirement; the signer only builds the domain `{name:"USDC", version:"2", chainId:84532, verifyingContract:USDC}`.

## Properties (fail closed, no `enabled` flag)
```properties
x402.server.pay-to=${X402_SELLER_PAYTO_ADDRESS}           # required iff any @RequiresPayment handler exists; 0x + 40 hex, checked at startup
x402.server.facilitator.url=https://x402.org/facilitator  # https required (http only for localhost/127.0.0.1)
x402.server.facilitator.read-timeout=15s
x402.server.max-timeout-seconds=60
x402.client.private-key=${X402_BUYER_PRIVATE_KEY}         # signer bean exists only if set; the interceptor needs it -> no key, no start
x402.client.max-amount-per-request=100000                 # atomic, required
x402.client.allowed-pay-to=0x...                          # required, non-empty
```
- Client refuses to pay when the request has no `Idempotency-Key` header.
- `@ConfigurationProperties` records holding secrets override `toString()`.

## Server flow
1. `RequiresPaymentInterceptor.preHandle`:
   - no `PAYMENT-SIGNATURE` → 402, `PAYMENT-REQUIRED` header, Problem Details body;
   - decode; `accepted` must exactly match the offer (scheme, network, asset, amount, payTo, maxTimeoutSeconds);
   - claim the nonce: key `x402:nonce:{network}:{asset}:{from}:{nonce}`, Valkey `SET NX` with TTL = `validBefore` − now + skew; claim fails → 402 (replayed);
   - facilitator `/verify`; invalid → release claim? no: keep the claim, 402.
2. Handler runs with the response buffered (`ContentCachingResponseWrapper` in `X402SettlementFilter`).
3. Handler 2xx → `/settle`: success → add `PAYMENT-RESPONSE`, flush body, publish `X402PaymentSettledEvent`; failure → drop body, 402, publish `X402PaymentFailedEvent`. Handler 4xx/5xx → never settled, nonce claim released, body passed through (not charged).
4. The on-chain EIP-3009 nonce is the final guard.
5. Resilience4j core: circuit breaker on both calls, retry with jitter on `/verify` only. `/settle` is **never** retried.

FakeFacilitator (test fixture): recovers the EIP-712 signer with web3j, checks the time window, value, payTo and asset, keeps used `(from, nonce)` pairs and answers `invalid_transaction_state` on reuse, supports failure injection.

## Observability (ADR-0006 amendment)
Only allowlisted key-values: low cardinality `x402.network`, `x402.scheme`, `x402.asset`, `x402.outcome`; high cardinality `x402.payer`, `x402.tx_hash`. An `ObservationFilter` strips any key matching a payment header name or containing `signature`, `payload` or `authorization`. Exceptions never carry payloads. Counter `x402.payments` (tags network, outcome) and a distribution summary `x402.payment.amount` in atomic units.

## Console buyer and make targets
`libs/x402-spring-boot-starter/samples/console-buyer` is a standalone Gradle build (own `settings.gradle.kts`, run with the root wrapper: `./gradlew -p libs/x402-spring-boot-starter/samples/console-buyer ...`) that resolves the starter from `mavenLocal()`. Commands (passed as `--args`):
- `buy --url=<url>`: pays and prints the body, the tx hash and a BaseScan link; stores the last payload in `build/last-payment.txt`.
- `replay --url=<url>`: resends the stored payload; exits 0 only if the server answers 402.
- `new-wallet`: writes a fresh key to `secrets/buyer.key` (mode 0600) and prints only the address.
- `testnet-check`: builds a signed payload for a seller address and calls x402.org `/verify` only (never `/settle`); read-only.
Key source: `X402_BUYER_PRIVATE_KEY`, else `secrets/buyer.key`.
