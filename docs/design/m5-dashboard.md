## Existing API (do not change behaviour)
- **orchestrator :8080** (`services/orchestrator/.../{run/RunController,events/RunEventController,approval/ApprovalController,approval/ApiRequestGuardFilter}.java`): `POST /api/v1/runs` `{question, budgetAtomic?}` → 202 `{runId, eventsUrl, traceId}` (JSON + `X-Saiman-Csrf: 1`); `GET /api/v1/runs/{id}` → RunSummary; `GET /api/v1/runs/{id}/events` SSE (`id` = seq, `Last-Event-ID` resumes, 204 when nothing left, 4 streams per run, 64 overall; `Accept: application/json` returns the ordered export); `POST /api/v1/runs/{id}/approvals/{approvalId}` `{decision}` (409 when expired/decided); `GET /api/v1/ping`.
- **ledger :8082** (`services/ledger/.../api/{ReconciliationController,TrialBalanceController,LedgerApiGuardFilter}.java`): `GET /api/v1/ledger/trial-balance`; `POST /api/v1/reconciliation/runs` (202 `{runId}`, 409 running, 429 `Retry-After`); `GET /api/v1/reconciliation/runs/{id|latest}`.
- Guards: exact Host allowlist (port stripped, so `localhost:<any>` passes), `X-Saiman-Csrf`, no authn until M6. seller-api and ingest are not called by the browser.

## Contracts and tooling
- Catalog: `libs.springdoc.openapi.webmvc.api` (3.1.1). **Spike result (2026-10-05):** resolves and runs on Boot 4.1.1 / Jackson 3 (OpenAPI 3.1.0), but ignores JSpecify `@Nullable`: no `required` arrays and no null markers, so a generated client would type every property as optional. **Each service therefore adds a small `OpenApiCustomizer` (same class name, e.g. `NullabilityOpenApiCustomizer`)** that marks every record component `required` unless it is `@Nullable`, and renders `@Nullable` ones as `type: [<t>, "null"]` (3.1 style; a `$ref` becomes `oneOf: [{$ref}, {type: "null"}]`), with a unit test on a sample record. Also: give inner records unique schema names (springdoc uses the simple name, so nested `Item`/`Summary` collide: use `@Schema(name = ...)` or full-name resolution), declare the real responses of `ResponseEntity<?>` handlers (typed `ReconciliationStarted`, 202/404/409/429 with `@ApiResponse`), check `BigInteger` fields (`TrialBalanceRow.debit/credit/balance` render as `integer` without format) and that `servers` stays normalised. `/v3/api-docs` is guarded like any other path (needs an allowed Host, e.g. `Host: localhost`). `OpenApiContractTests` per service (orchestrator, ledger) with Testcontainers via `libs/test-support`, `Host: localhost`, normalised (sorted keys, `servers` cleared) vs `docs/api/<service>.openapi.json`.
- Web: `pnpm gen:api` (`openapi-typescript`, version pinned in `package.json`) → `web/src/lib/api/generated/{orchestrator,ledger}.ts`; `openapi-fetch` typed client; CI and `make lint` run the `--check`.
- Run events: `docs/events/agent.run-step.v1.schema.json` + `libs/shared/src/test/resources/fixtures/events/agent.run-step.v1/<TYPE>.json` generated by a write-mode test over every sealed `RunEventData` subtype; web `web/src/lib/api/run-events.ts` union + guard, Vitest against the same files.

## Web (`web/`)
- **Routes** (TanStack file routes): `/` landing (what Saiman is, testnet/local-only banner, CTA, system status with fix hints, recent runs), `/runs`, `/runs/new`, `/runs/$runId`, `/approvals`, `/spend`, `/ledger`, `/ledger/payments/$paymentId`, `/reconciliation`, `/reconciliation/$reconRunId`, `/revenue`. Nav badge for pending approvals (poll 5 s) and a document-title prefix.
- **State:** `queryOptions` factories in `web/src/lib/api/queries.ts`; keys `['runs',…]`, `['approvals','pending']`, `['spend',day]`, `['ledger',…]`, `['reconciliation',…]`. `useRunEvents(runId)`: native `EventSource` for non-terminal runs (browser sends `Last-Event-ID`), merge by `seq`, invalidate payments/summary/approvals/spend on `PAYMENT_*`, close and invalidate ledger queries on the terminal event; terminal runs read the JSON export (`staleTime: Infinity`).
- **First-run flow:** CTA → `/runs/new` (pre-filled example question chip, default budget from `/api/v1/spend`, plain text on the approval threshold and "approval never raises the budget", "do not enter personal data") → `/runs/$id` (stepper PLANNER/RESEARCHER/RISK/SYNTHESIS, budget meter, payments panel with Basescan links) → inline approval card (amount, payee, resource, countdown to `expiresAt`, Approve/Reject, assertive live region) → report (citations as text; link only code-validated `https://www.kap.org.tr/` URLs with `rel="noopener noreferrer"`) → "In the ledger" panel polling `ledger/payments?runId` every 2 s up to 60 s, linking to the drill-down.
- **States:** skeletons; empty states with a CTA; Problem Details `detail` shown as-is (fixed server text); 429 → "retry in N s", 503 NOT_READY → "starting", 409 approval → refetch.
- **Money:** `web/src/lib/money.ts` `formatMoney({atomicUnits, asset, decimals})`, BigInt/string only, refuses non-`Number.isSafeInteger` input (renders "—" with a title); LLM cost is USD micros (`$0.0069`); table tests.
- **Accessibility:** landmarks, skip link, one `h1` per page, labelled controls, visible focus, status not by colour alone, AA contrast, table `caption`/`th scope`, `lang="tr"` on question/answer/citations, polite live region for steps (throttled), no per-second countdown announcements, `prefers-reduced-motion`.
- **Replay-ready:** `apiGet(path)` (`web/src/lib/api/source.ts`) for every read, `subscribeRunEvents` for streams, mutations hidden when `VITE_DEMO_MODE=replay`; the e2e fixture server `web/e2e/fixture-server.ts` implements the capture format (stateful start/approve, scripted SSE with `retry:`).
- **Tests:** Vitest (money, run-event guard, reducers, components); Playwright `e2e/acceptance.spec.ts` (landing → start run → approve → ledger entries visible) with `@axe-core/playwright` in every spec; `web/scripts/lighthouse.mjs` (`lighthouse` Node API, accessibility only, every route of `vite preview` against the fixture server, fails below 0.90, reports in gitignored `web/reports/lighthouse/`, `CHROME_PATH` = Playwright's Chromium; `engines.node` ≥ 22.19).
