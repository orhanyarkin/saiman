# M6 design: auth, DB roles, evals, mismatch event, replay, settle diagnostics

ADRs: 0023 (auth), 0024 (DB roles), 0025 (evals), 0026 (replay + cap fallback). Out of this plan (human-only or deferred): Terraform `demo-lite`, Infracost, AWS capture session, Cloudflare deploy, blog, video, Grafana screenshots, cross-provider route comparison and LLM judge (needs new provider keys).

## Assumptions (decided by the orchestrator, flagged to the human)
1. One human token per role shared by orchestrator and ledger; service tokens per caller.
2. Tier A evals use an unpaid, service-token-guarded `POST /internal/v1/eval/questions` on seller-api (bounded by run guard and day cap); evals never pays x402.
3. No LLM judge / no multi-provider comparison in M6; PLAN updated accordingly.
4. Kafka/Redis authentication and ingest `/internal` auth stay deferred (THREAT_MODEL revisit targets moved; ingest auth is cheap later with `libs/api-security`).
5. The settle rule "never retry /settle" (ADR-0008) stays; the failure investigation is data-first.

## Human refinements (2026-10-05)
- The eval endpoint `/internal/v1/eval/**` is **never routed by nginx** (compose policy/`check-nginx-conf.sh` fails if any `/internal` location exists; add a test) and **writes nothing to the ledger**: no payment row, no outbox/Kafka event, no credit note. The seller-api test asserts the payment/outbox tables and topics are unchanged after a call.
- All other assumptions above approved.

## B1. Auth contract (`libs/api-security`, package `io.github.orhanyarkin.saiman.apisecurity`)
- `SaimanRole {READER, OPERATOR, SERVICE}` (authority `ROLE_<name>`), `SaimanAuthorities.service(caller)` = `SERVICE_<caller>`; `RoleHierarchy` `ROLE_OPERATOR > ROLE_READER`.
- `StaticTokenIntrospector implements OpaqueTokenIntrospector` (regex `^[A-Za-z0-9_-]{32,128}$` first; SHA-256; `MessageDigest.isEqual` against every digest; principal name `<role>:<8 hex of digest>`, attribute `roles`).
- `SaimanResourceServer.apply(HttpSecurity, OpaqueTokenIntrospector)`: stateless, csrf off, no formLogin/httpBasic/logout, header-only bearer, `ProblemAuthenticationEntryPoint` (401 + `WWW-Authenticate: Bearer`), `ProblemAccessDeniedHandler` (403), fixed texts.
- Auto-config `ApiSecurityAutoConfiguration` (`saiman.auth.enabled`, default true); properties `saiman.auth.reader-token-sha256[]`, `operator-token-sha256[]`, `service.tokens.<caller>.sha256`. Env: `SAIMAN_AUTH_READER_TOKEN_SHA256`, `SAIMAN_AUTH_OPERATOR_TOKEN_SHA256`, `SAIMAN_AUTH_SERVICE_TOKENS_LEDGER_SHA256`, `SAIMAN_AUTH_SERVICE_TOKENS_EVALS_SHA256`. Raw tokens: `secrets/api_reader_token`, `api_operator_token` (humans/Make only), `seller_service_token_ledger` (ledger only → `saiman.ledger.seller.service-token`), `seller_service_token_evals` (evals only → `saiman.evals.seller.service-token`). Ledger fails startup if `saiman.ledger.seller.base-url` is set and the token blank.
- Guard filters `ApiRequestGuardFilter`/`LedgerApiGuardFilter` get `@Order(SecurityProperties.DEFAULT_FILTER_ORDER - 10)`. Permit ASYNC/ERROR dispatch (SSE) then `anyRequest().denyAll()`.
- Orchestrator: `GET /api/v1/me` → `{name, roles}`; `approval.decided_by`; `bearerAuth` scheme in springdoc (both services); OpenAPI snapshots and `gen:api` rerun.
- Web: token context + Connect dialog, `Authorization` on every request, `web/src/lib/api/sse.ts` (fetch + ReadableStream; `Last-Event-ID`, `retry:`, stop on 204/terminal/401, backoff ≤ 30 s), ESLint ban on `localStorage`, role-aware UI from `/me`.

## B3. Mismatch event
Add `CREDIT_NOTE_UNCORROBORATED` to `MismatchKind` and the schema enum in `docs/events/ledger.reconciliation-mismatch.v1.schema.json` + golden fixture. Topic stays v1; `docs/events/README.md` gets "consumers treat an unknown `kind` as a generic finding". Semantics: `ledgerAmount` = credited amount, `reportedTxHash` = seller tx from the books; `chainAmount`, `chainTxHash`, `adjustmentEntryId` null. Producer: `ReconciliationService.uncorroborated()` publishes `ReconciliationMismatch` through the outbox in the same transaction, only when `insertMismatch` inserted the row (name-based id; pre-M6 findings are not republished). Web bug: `ledger-model.ts` maps `SELLER_CREDIT_UNCONFIRMED`, the API returns `CREDIT_NOTE_UNCORROBORATED`: fix + test.

## B4. Eval contract (`libs/shared`, package `eval`)
`EvalAnswerRequest(String ticker, String question)`, `EvalAnswerResponse(EvalOutcome outcome, @Nullable String answer, List<EvalCitation> citations, long modelCostUsdMicros)`, `EvalOutcome {ANSWERED, NO_VALID_CITATIONS, REFUSED, LLM_CAP, ERROR}`, `EvalCitation(chunkId, sourceUrl, publishedAt)`. Config `saiman.evals.*`: `run-on-startup`, `golden-set`, `output-dir`, `ingest.base-url`, `seller.base-url`, `seller.service-token`, `retrieval.top-k=10`, `answers.enabled=false`, `answers.max-questions=30`, `answers.stop-on-cap=true`. Cost: Tier R ≈ $0.00002/run, Tier A ≈ $0.06/30 questions (≈9 % of the $0.70 day cap).

## B6. Settle telemetry (starter)
Observations `x402.facilitator.settle` / `.verify`; low-cardinality keys `outcome ∈ {success, rejected, ambiguous, transport_error, circuit_open, malformed}` and `reason` from the closed enum `FacilitatorReason` (known x402 exact-EVM codes incl. `invalid_exact_evm_transaction_failed`, `settlement_pending`, `insufficient_funds`, `none`, `other`; unknown shape-valid codes → `other`, the log keeps the code). `x402.payments{outcome=failed}` gets the same `reason` tag. One WARN per settle failure with only: reason, attempt id, payer, `nonceRef` (first 8 hex of sha256(lowercase from+nonce)), `validAfter`/`validBefore`, seconds left at settle, verify→settle gap ms, settle duration ms, facilitator HTTP status, `txHashPresent` (+ tx hash if well formed). Never: signature, payload, facilitator `errorMessage`, nonce. Investigation plan: `docs/ops/facilitator-settle-failures.md` (H1 receipt wait failed / chain USED, H2 facilitator sender nonce or gas dropped / chain UNUSED, H3 included after `validBefore`; H4 funds/double settle excluded; decide mitigation after ~20 settles or 3 failures; upstream refs x402 exact EVM spec `settlement_pending`, issue #2471).

## Risks
Async dispatch + Spring Security for SSE (T2 real-Tomcat test is the proof); seller-api `securityMatcher` must not disturb x402 header handling; pgvector as non-owner (fallback: `db-init`/test-support create the extension); `docker compose up --wait` with one-shots (fallback: Make runs `compose run --rm db-init`); adopting pre-M6 objects must cover every object type; mid-run cap after upfront settle still yields a credit note; recency leg may hurt general retrieval (report compares); golden set tied to `corpusVersion`.
