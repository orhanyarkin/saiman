# ADR-0025: Eval harness

Status: Accepted (2026-10-05). Builds on ADR-0003 (judge independence), ADR-0010 (frozen corpus), ADR-0012 (retrieval).

## Context
M6 needs a published, repeatable measure of RAG quality and cost, including whether "latest disclosures" questions return the newest documents. The corpus is a frozen 2023 snapshot, so "latest" means latest in the corpus.

## Decision
- **Golden set** `services/evals/src/main/resources/golden/golden-set.v1.yaml`: metadata only (disclosure indexes, dates, short facts). No KAP text is committed (rule 8). About 30 items (26 in v1: only 16 of the 20 configured tickers have indexed disclosures): `RETRIEVAL` (one per indexed ticker), 3 `FRESHNESS` (incl. "THYAO son özel durum açıklamaları"), 5 `ANSWER`, 2 `UNANSWERABLE`. **`ANSWER` items are two-source questions** (two disclosures of one ticker, one required date fact from each): the answer service answers only with at least two valid citations, so single-disclosure items score `NO_VALID_CITATIONS` and measure the labels rather than the product (first live run: task success 0.000 with fact and citation recall 1.000; after relabelling 1.000; numbers in `docs/evals/README.md`). A single-source question kind can be added if the service's citation rule changes. Labels are made once with documented SQL against the local ingest DB; the file records `corpusVersion` and the run warns when it is stale.
- **Metrics at disclosure level** (chunks deduplicated by the `kap:<index>:` prefix, first rank kept). RETRIEVAL: Recall@10, MRR@10, graded nDCG@10. FRESHNESS with L = the 5 newest disclosures of the ticker: `recency@5 = |top5 ∩ L| / 5`, `latestHit@5`, nDCG@10 with gain `6 − rank` for members of L. ANSWER/UNANSWERABLE (deterministic, no judge): citation validity, citation recall, required-fact match, refusal correctness. Targets are reported, not CI-gating.
- **Recency leg in ingest.** RRF has no recency signal today. Recency intent is detected in code (`son`, `en son`, `güncel`, `yeni`, `latest`, `recent`) and adds a third RRF leg: the newest INDEXED documents for the tickers by `published_at DESC`. The leg's RRF term is weighted (`saiman.ingest.retrieval.recency-weight`, default 3.0) because plain equal-weight RRF barely moved freshness on the baseline (recency@5 0.07 to 0.20 in a replay); the leg fires only when intent is detected, so results without intent are bit-identical to the two-leg result. The weight was set on three FRESHNESS items and is a hypothesis the live eval must confirm (T8). No change to the `libs/shared` retrieval contract. The report shows before/after for every kind; the leg must not hurt RETRIEVAL.
- **Two tiers.** Tier R (default `make eval`): `POST ingest /internal/v1/retrieve`, cost ≈ embeddings only. Tier A (`make eval EVAL_ANSWERS=1`): `POST seller-api /internal/v1/eval/questions`, requires `SERVICE_evals`, runs the same answer service (real prompt, parser, citation rebuild) without x402, guarded by a run guard (caller `evals`, 1 in flight, 60/h, 100/day) and the router day cap. It never settles or records a payment. Outcomes: `ANSWERED` (>= 2 valid citations), `NO_VALID_CITATIONS` (the model ran, fewer than 2 citations; the answer text is returned), `REFUSED` (before any model call: ticker not indexed or fewer than 2 usable excerpts), `LLM_CAP`, `ERROR`; guard refusals are HTTP 429/503, not outcomes. Excerpts carry a `published:` line so date facts are answerable (this also applies to the paid questions endpoint).
- **No LLM judge, no cross-provider route comparison in M6.** ADR-0003 needs a different model family for a judge and that needs new paid provider keys (stop-and-ask). PLAN is updated; add providers later only with the human's go.
- **Run and output.** `evals` is a compose one-shot (profile `evals`, on the compose network so Host allowlists hold; only secret: its service token; only writable mount `build/evals`). Reports: `docs/evals/latest.md`, `latest.json`, `runs/<date>-<sha>.json` (corpus version, git sha, models, cost).

## Consequences
+ Free, repeatable, committed numbers; measures the product's real prompt.
− Eval calls share the router day cap with paid traffic: exhausting it makes paid calls 503 with a credit note until 00:00 UTC (the daily run limit bounds this).
− An unpaid internal path to an LLM function exists (bounded by service token, run guard and day cap; same trust level as ingest's `/internal/v1/retrieve`). Labels must be redone after re-ingest.

## Alternatives
Evals paying x402 itself (needs the buyer key, breaks K1, needs a full spend guard); copying the prompt into evals (measures a copy); LLM-as-judge now (provider approval).
