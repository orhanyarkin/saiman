# ADR-0023: API authentication with static role tokens behind Spring Security's resource-server seam

Status: Accepted (2026-10-05; human chose static role tokens, OIDC/JWT as the documented upgrade path). Amends ADR-0022 (authentication added, SSE via `fetch`; still same-origin, no CORS) and ADR-0018 (authn pointer).

## Context
The orchestrator and ledger APIs have only a Host allowlist and a CSRF header (ADR-0022). Anything on the machine can start runs, approve payments and trigger reconciliation. Before anything is shown publicly the APIs need authentication and two privilege levels, without running an identity provider.

## Decision
- **Static role tokens.** Roles `READER` (all GETs), `OPERATOR` (includes READER: start runs, decide approvals, run reconciliation; `RoleHierarchy`) and `SERVICE_<caller>` (internal calls, e.g. `SERVICE_ledger`, `SERVICE_evals`). Services hold only **SHA-256 digests** of tokens (env `SAIMAN_AUTH_*_SHA256`, not secrets); raw tokens live in `secrets/` (ADR-0009), generated by `ensure-secret-files.sh`, mounted only where used. Digest comparison is constant time over every configured digest (no early exit); tokens must match `^[A-Za-z0-9_-]{32,128}$` before hashing. Startup fails on no digest, a malformed digest, or one digest in two roles.
- **One token per human role, shared by orchestrator and ledger** (the dashboard asks for one token). Service tokens are per caller.
- **The seam.** New `libs/api-security`. Each service uses `oauth2ResourceServer().opaqueToken()` with a custom `OpaqueTokenIntrospector` (`StaticTokenIntrospector`), the only class that knows tokens are static. `SaimanResourceServer.apply(http, introspector)` is the one place the authentication mechanism is chosen (stateless, no cookies, bearer from the header only, fixed RFC 9457 401/403 bodies). Request rules live in a per-service `ApiSecurityConfiguration`, separate from the verifier. Controllers use no security API except reading the principal name.
- **Rules.** Orchestrator: health open; `GET /api/v1/**` (incl. SSE and `/me`) READER; `POST /api/v1/runs`, approval decisions OPERATOR; rest denied. Ledger: GETs READER; `POST /api/v1/reconciliation/runs` OPERATOR. seller-api: `securityMatcher("/internal/**")` only (the paid `/v1/**` path and x402 never pass through Spring Security); `/internal/credit-notes/**` needs `SERVICE_ledger`, `/internal/v1/eval/**` needs `SERVICE_evals`.
- **Existing guards stay** (Host allowlist, path canonicalisation, `X-Saiman-Csrf`, body size) and run before the security chain. Spring's CSRF is off (bearer, no cookies).
- **SSE** is read with `fetch` + a small `text/event-stream` parser in the SPA (headers `Authorization`, `Last-Event-ID`). Nothing goes in the URL. A single-use ticket is rejected (server state, ends up in access logs); `@microsoft/fetch-event-source` is rejected (unmaintained).
- **Dashboard token handling.** Held in memory (React context); an opt-in "keep for this tab" uses `sessionStorage`. **Never `localStorage`** (lint rule + test). nginx injects nothing (policy script fails on `proxy_set_header Authorization`). The README documents this.
- **Audit trail.** Approvals record `decided_by` (principal name, `<role>:<8 hex of digest>`).

## Upgrade path: OIDC / JWT
Replace `.opaqueToken(...)` in `SaimanResourceServer.apply` with `.jwt(...)` and a converter mapping a `roles` claim to the same `ROLE_*`/`SERVICE_*` authorities; add `issuer-uri`. Controllers, rules, `RoleHierarchy`, `/me` and the web are unchanged. With JWTs, open SSE streams must be closed at `exp`.

## Consequences
+ Real authn/authz now, no new service, no cost; the later swap is one method.
+ Raw tokens never sit in service config; services can't leak them.
− Static tokens: no expiry, rotation = redeploy, no per-user identity. Acceptable for a testnet portfolio demo; the UI says so.
− Kafka, Redis and ingest `/internal` stay unauthenticated (deferred, THREAT_MODEL).

## Alternatives
Hand-written filter (reinvents the seam); cookies + CORS; nginx injecting the token (anyone reaching nginx is then authenticated); Keycloak/OIDC now (new service and ops cost).
