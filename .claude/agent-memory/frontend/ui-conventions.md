Conventions from building `web/` in M0 (ADR-0002 SPA, ADR-0006 tracing). Re-derive from the
current tree if this drifts — this is a snapshot, not a contract.

**Layout**: `src/routes/` (TanStack Router file-based, `__root.tsx` + one file per route),
`src/routeTree.gen.ts` (generated by `@tanstack/router-plugin`'s Vite plugin — **commit it**, it
self-excludes from lint/format via its own `/* eslint-disable */` + `// @ts-nocheck` header, and
is also explicitly ignored in `eslint.config.js` and `.prettierignore` for belt-and-suspenders).
Regenerate by running `pnpm exec vite build` (or `pnpm dev`) once after adding/removing a route —
`pnpm build`'s `tsc -b` runs *before* `vite build`, so a fresh clone needs the generated file
already committed or typecheck fails on the missing module.

`src/components/ui/` holds hand-written shadcn/ui components (Button, Card only in M0), matching
shadcn's own generated output (cva variants, `data-slot` attributes, `cn()` from
`src/lib/utils.ts`). `components.json` is present for future `shadcn` CLI additions even though
M0 didn't run the CLI (network/interactivity concerns) — components were hand-authored to match
its conventions exactly. shadcn's `CardTitle` renders a plain `<div>` (by design — Card is a
generic container, not tied to a heading level), so it has no real accessibility semantics on its
own; get a real heading by nesting one at the *usage site* (`<CardTitle><h2>...</h2></CardTitle>`)
rather than editing the shared primitive.

**ESLint flat config** (`eslint.config.js`): `eslint-plugin-react-hooks` 7.x's flat-format config
is at `reactHooks.configs.flat["recommended-latest"]`, NOT `reactHooks.configs["recommended-latest"]`
(that one is eslintrc-style with `plugins: ["react-hooks"]` as an array, which ESLint flat config
rejects outright). `react-refresh/only-export-components` is turned off for `src/components/ui/**`
(shadcn intentionally co-exports `buttonVariants` alongside `Button`) and for `src/routes/**`
(TanStack Router files only export a `Route` object, which the rule doesn't recognise as
component-shaped).

**Telemetry** (`src/lib/telemetry.ts`): all `ImportMetaEnv` fields are `readonly VITE_X?: ...`
(optional) in `vite-env.d.ts`, because production/replay builds don't load `.env.development`.
`initTelemetry()` is guarded three ways: a module-level `initialised` boolean (idempotent — safe
to call more than once), a check that `VITE_OTEL_ENABLED === "true"`, and — since the URL is now
optional — a `console.warn` + early return if `VITE_OTEL_TRACES_URL` is unset while enabled.
Called once in `main.tsx` before `createRoot(...).render(...)`. Uses `WebTracerProvider` (which
registers `StackContextManager` by default — no `ZoneContextManager` needed, the fetch span is the
trace root) + `BatchSpanProcessor(OTLPTraceExporter)` + `FetchInstrumentation` with `ignoreUrls`
**derived from `VITE_OTEL_TRACES_URL`** (a regex built from the escaped configured URL), not a
hardcoded `/\/otlp\//` — so a differently-pathed exporter endpoint in a future live deployment is
still excluded correctly. See [[web-stack-pins]] for the jsdom/PerformanceObserver testing gotcha
this produced.

**API calls (M5 T3a)**: every read goes through `apiGet`, mutations through `apiPost` (always
`Content-Type: application/json` + `X-Saiman-Csrf: 1`, disabled when `VITE_DEMO_MODE=replay`), live
runs through `subscribeRunEvents` (native `EventSource`) — all in `src/lib/api/source.ts`. Non-2xx
becomes a typed `ApiError` (`kind`: conflict/rate-limited/not-ready/...; `detail` = fixed Problem
Details text, `retryAfterSeconds`). `queries.ts` holds `queryOptions` factories + `queryKeys`;
`types.ts` is the ONE place response types live (hand-written until T3b/T3c swap in generated
openapi-typescript types). `run-events.ts` = hand-written 14-event union + `parseRunEvent` guard,
tested against the shared golden fixtures. Money only via `lib/money.ts` (BigInt/string, no floats).
Pure reducers for the run page live in `lib/run-view-model.ts` (no React). Components handle
loading (`role="status"`), error (`ErrorNotice`, `role="alert"`) and empty states.

**Accessibility conventions**: skip link + `<main id="main" tabIndex={-1}>` in `__root.tsx`; one h1
per route; approval card = labelled `region` + one static sr-only `role="alert"` line (buttons stay
outside the alert), countdown `aria-hidden`; step changes via a throttled polite `role="status"`;
status always glyph + text, never colour only; `--ring`/`--muted-foreground` darkened for AA.

**e2e**: `pnpm e2e` runs `e2e/fixture-server.ts` (port 4010) + Vite in fixture mode
(`SAIMAN_API_TARGET`, port 5174) — `reuseExistingServer: false`. The fixture server is also
unit-tested in `pnpm test` (`e2e/fixture-server.test.ts`; vitest excludes only `e2e/**/*.spec.ts`).
Proxy table is `web/proxy.ts` (ledger regex key BEFORE catch-all `/api`, pinned by `proxy.test.ts`).

**Testing**: `src/test/setup.ts` imports `@testing-library/jest-dom/vitest` (not the bare
`"@testing-library/jest-dom"` import — that resolves to the default export path whose bundled
`jest.d.ts` reference breaks typecheck when `@types/jest` isn't installed). Query client in tests
gets `defaultOptions: { queries: { retry: false } }` so error-state tests don't wait through
retry backoff. `vite.config.ts`'s `test.exclude` includes `e2e/**` so `vitest run` never picks up
Playwright specs.
